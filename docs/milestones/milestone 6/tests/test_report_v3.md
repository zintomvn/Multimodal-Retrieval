## Actual end-to-end runs

### Default DEV run (85 diverse videos)

The first complete five-query run returned exactly five items for every query.
The candidate pool was 85 distinct videos (`top_k + 80`), and the sequence
pool had 63--85 temporal candidates before final top-5 selection.

| Query | Runtime | Sequence pool | GT video in final top-5 | Result |
| --- | ---: | ---: | --- | --- |
| p2-1 | 56.54 s | 77 | rank 2 | pass at video level |
| p2-2 | 47.28 s | 85 | rank 1 | pass at video level |
| p2-3 | 55.57 s | 83 | no | fail |
| p2-4 | 63.88 s | 63 | no | fail |
| p2-11 | 58.03 s | 63 | no | fail |

After the DEV fixes below, p2-1 and p2-2 were rerun with frame-index output:

| Query | Runtime | Final GT-video rank | Returned frame index | GT frame index | Delta |
| --- | ---: | ---: | ---: | ---: |
| p2-1 | 69.37 s | 3 | 5147 | 5111 | 36 |
| p2-2 | 28.20 s | 1 | 1781 | 1514 | 267 |

These are correct-video top-5 hits. Whether their index deltas count as an
exact benchmark hit must use the evaluator's keyframe tolerance; the search
service must not compare CSV indices to timestamps.

### Negative controls: do not increase Milvus work without evidence

I tested the user's proposed larger global pool at the configured safety cap
of 160 distinct videos. It did **not** recover any failed GT video and raised
latency substantially:

| Query | Runtime with 160 videos | Sequence pool | GT in top-5 |
| --- | ---: | ---: | --- |
| p2-3 | 76.63 s | 43 | no |
| p2-4 | 89.19 s | 17 | no |
| p2-11 | 67.56 s | 29 | no |

The configuration is therefore kept at 85 videos for `top_k=5`: it is already
well above `k`, returns five final frames, and avoids a 20--40% latency cost
that did not improve recall. The code still expands the pool as requested for
larger `top_k` values, up to the 160-video cap.

An explicit diagnostic `min_match=1` was also tested on p2-3/p2-4/p2-11 after
the fixes. It did not recover a GT video in the final five (runtimes 78.67 s,
85.88 s, and 69.74 s respectively). The production default remains two matched
events for a multi-event query, which is the safer noise filter.

A bounded whole-narrative coarse probe was then added experimentally (at most
16 supplemental videos) for p2-3 and p2-4. It produced 90 and 89 candidate
videos, took 78.68 s and 61.21 s, and recovered neither GT video. The code was
removed again; it is not part of the final DEV configuration.

## Module-level diagnosis

### 1. Global event-video recall is the bottleneck for p2-3 and p2-4

Whole-query, non-temporal diagnostics can see the GT video: p2-3 has GT-video
rank 23 and p2-4 rank 11 among 1,000 global frame results. Their event-only
DEV probes nevertheless did not retain the GT video/frame in the final
sequence. Thus simply widening the selected-video pool is not the fix: the
coarse event descriptions are too generic (ingredients being added; teacher
and slide text) to preserve the discriminative video/frame evidence.

### 2. p2-11 is a hard final-visual-state query, not a language-only issue

The terminal visual event generated by the new planner,
`Finished product becomes white and fluffy, resembling interlinked threads on a white surface`,
retrieves `L26_V483` at rank 1 in an isolated visual diagnostic, with frame
index 590. A concise conjunction probe (`white puffed strands stuck together
arranged on a white tray`) retrieves it at rank 6. However the ordered DEV
sequence still omits that video from final top-5, and the one-event diagnostic
fallback also did not recover it. This localises the remaining failure to
event-plan consistency and sequence competition, rather than a lack of
OpenCLIP/SigLIP2 visual capability.

### 3. Fixed DEV bug: bilingual SigLIP2 view was discarded

`_resolve_temporal_event_plans` rebuilt each event plan but failed to copy
`siglip2_views` and `diagnostic_prior`. Consequently, the Vietnamese visual
view requested by the agent prompt never reached the second, video-filtered
Milvus retrieval. DEV now preserves both fields. A regression test verifies the
contract.

### 4. Temporal semantics and sampling

- Local search is a second Milvus retrieval constrained to the selected video
  IDs; it is not a post-filter over global frames.
- Ordering is strict by timestamp and respects planner edge/delta constraints;
  close events are allowed. Gap scoring now uses the configured 45-second
  reference instead of a hard-coded 300-second reference.
- Dynamic sampling is bounded to the temporal window and only exposes context
  for uncovered AutoShot intervals. It does not fabricate semantic evidence or
  promote a noisy video.
- Dynamic samples are generated only for final top-k sequences, avoiding
  discarded-sequence database lookups.

## Prompt audit and new version

All existing prompts under `configs/agent prompt/` were inspected:

| Version | Finding |
| --- | --- |
| v1 | Stable English baseline, but weak on model-specific bilingual visual states. |
| v2 | Vietnamese semantic requirement conflicts with the previous English-preference path. |
| v3 | Introduced bilingual views but optional fields were often omitted. |
| v4 | Captures the p2-11 appearance state well, but its long schema reduces structured-output reliability. |
| v5 | New active compact contract. It makes event order, weights, English CLIP views and Vietnamese `siglip2_views` required, while keeping the hard visual state as one semantic conjunction. |

New file: `configs/agent prompt/agent_v5_dev_compact_contract.md`. No earlier
prompt was overwritten. A p2-3 plan emitted four ordered English events and
the bilingual SigLIP2 descriptions, confirming v5 can satisfy the required
retrieval format.

## DEV-only changes

- Diverse video selection from all global event probes; `top_k=5` selects 85
  videos before the filtered local pass.
- Two bounded semantic/text views locally, with a Vietnamese SigLIP2 view in
  `both`/`siglip2` mode.
- Event importance and diagnostic priors are retained instead of replaced by
  uniform heuristic weights.
- Explicit `min_match=1` is now honored for controlled sparse-AutoShot
  diagnostics; the default multi-event noise guard remains two events.
- No ATS or old Vortex temporal filtering is used in the DEV route; it uses
  the DEV local Vortex temporal scorer after global diagnostic selection.

## Conclusion

The requested five-query execution was performed. The current verified result
is **2/5 GT videos in top-5**, not 5/5, so claiming success would be incorrect.
The next targeted improvement is to record per-event GT-video membership and
per-event local-frame rank before sequence construction, then improve only the
failed checkpoint. Both a 160-video pool and a bounded narrative probe have
now been measured and rejected, so a blindly wider Milvus window is not a
useful substitute.
